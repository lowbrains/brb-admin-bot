# Администратор БРБ — Telegram-бот

Бот рабочей группы Блока развития бизнеса: отвечает на обращение, помнит последние
сообщения группы, предлагает карточки поручений с подтверждением кнопкой.

Написан на **голой стандартной библиотеке Python** — ни одной внешней зависимости
в сервисном пути. Отсюда и образ без `pip install`.

## Что умеет

| Команда | Что делает |
|---|---|
| `/ping` | проверка связи |
| `/team` | состав команды из `runtime/team.txt` |
| `/tasks` | подтверждённые поручения, последние 15 |
| `/help`, `/?` | справка |
| обращение к боту | ответ модели + до 3 черновиков поручений |

Обращением считается упоминание `@<имя бота>`, начало сообщения с «Бот, …» / «Bot, …»,
команды `/ask` и `/summary`, либо ответ на сообщение бота. Обычная переписка **молча
сохраняется локально и наружу не уходит** — модель видит контекст только при обращении.

## Чего пока нет

Календарь, учёт отпусков, рассылки, напоминания. Файлы и голос не расшифровываются.
Персональной привязки сотрудников к Telegram-аккаунтам нет: доступ определяется
членством в закрытой группе. Поручения августовской сессии (`runtime/data/session-01-actions.json`)
в `/tasks` не подключены. Подробности и ограничения — в [docs/DISCUSSION.md](docs/DISCUSSION.md).

## Устройство

```
src/discussion.py     сервис: приём Telegram, память, вызов модели, карточки
tests/                21 тест, внешняя сеть не нужна
config/*.example.json шаблоны конфигурации
scripts/              разовые импортёры и Windows-обвязка ввода ключей
legacy/bot.ps1        первая PowerShell-версия (только /ping /team /help)
docs/DEPLOY.md        выкладка на сервер
runtime/              ⛔ данные и секреты, вне git
```

`runtime/` — это рабочее состояние: `team.txt`, `config/`, `data/discussion.sqlite3`,
переписка группы, PDF сессии. Персональные данные сотрудников. **В репозиторий не попадает
и попадать не должно** — см. `.gitignore`.

## Сеть

Бот ходит в два внешних адреса: `api.openai.com` (модель) и `api.telegram.org`.
Сервер стоит в Нидерландах, оба адреса доступны напрямую — прокси не нужен.

Маршрут каждого адресата всё же вынесен в переменную, потому что они могут
оказаться по разные стороны границы: с российского адреса доступен Яндекс, но
не OpenAI, с зарубежного наоборот. Пустая переменная — прямой маршрут.

```
TELEGRAM_PROXY   маршрут до Telegram
MODEL_PROXY      маршрут до модели
```

Переменные независимы, и ни один адресат не подхватывает `HTTPS_PROXY` из
окружения — иначе рабочая переписка уехала бы в туннель незаметно. Проверяется
`tests/test_routing.py`, а не обещается здесь.

Прокси, если он появится, используется через `CONNECT`: токен бота лежит прямо
в пути URL Telegram, и так он остаётся внутри TLS.

## Модель

OpenAI Responses API, `gpt-5-mini`, `store: false` — ответы у провайдера не
сохраняются. Endpoint и модель задаются в `runtime/config/discussion-config.json`;
смена модели — одна строка, кода не касается.

Код понимает две формы API: путь, оканчивающийся на `/responses`, и всё
остальное как Chat Completions. Переключение — тем же полем `model_endpoint`.

## Запуск

```bash
cp .env.example .env                  # вписать токен, ключ, chat_id
mkdir -p runtime/config runtime/data
sudo chown -R 10001:10001 runtime     # на Linux обязательно: процесс не от root
docker compose up -d --build
docker compose logs -f bot
```

Ожидаемая первая строка в журнале:
`Обсуждения: запущено. Переписка хранится 30 дней; ответы по обращению.`

Перед запуском в `runtime/` должны лежать `team.txt`, `config/discussion-config.json`
и (если не задан `BRB_CHAT_ID`) `config/connection.json`.

> **Одновременно может работать только один приёмник.** Ноутбучная копия и контейнер
> вместе дадут HTTP 409 и потерю апдейтов. `bot.lock` этого не поймает — он локален
> для машины.

Тесты:

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -t tests
```

## Требования к боту в BotFather

`/setprivacy` → Disable, затем удалить бота из группы и добавить заново. Без этого
`getMe` вернёт `can_read_all_group_messages: false`, и сервис откажется стартовать.
