# Обсуждения БРБ: подготовленный пилот

Ещё не запущен. Нужны выбранный провайдер модели и параметры сервера.
Код использует HTTPS API формата Chat Completions. Совместимость конкретного провайдера проверяется после выбора.

Возможности: локальное хранение текстов и подписей к сообщениям, связи ответов и правок; ответы по обращению; краткие итоги последних сообщений; черновики поручений с кнопками подтверждения и отмены; просмотр записанных поручений.

Обычная переписка сохраняется молча. При обращении к боту модели передаются до 60 последних сообщений текущей группы (до 24 000 символов), состав команды и текущая дата. Это ограниченное окно, а не полная память всех обсуждений. Telegram Bot API не загружает историю группы до подключения. Файлы и голос не расшифровываются, календарь и старые поручения в контекст пока не подключены.

Подтверждать карточку может автор запроса, по Telegram ID. Это подтверждение записи, а не подтверждение принятия поручения исполнителем. Привязка сотрудников к аккаунтам и подтверждение исполнителем — следующий этап. Карточка истекает через 24 часа. Повторное нажатие не создаёт дубль. Модель не имеет инструментов для выполнения действий.

## Подключение после выбора провайдера

1. Остановить старый bot.ps1. Одновременный запуск двух получателей Telegram недопустим.
2. В BotFather: /setprivacy, выбрать бота, Disable. Удалить бота из группы и добавить снова для применения. Проверить ту же группу.
3. Скопировать discussion-config.example.json в discussion-config.json. Указать HTTPS endpoint выбранного провайдера, модель и разрешение allow_context_transfer после согласования передачи рабочей переписки.
4. Секреты TELEGRAM_BOT_TOKEN и MODEL_API_KEY вводятся скрыто при запуске или задаются в окружении сервиса. Не записывать их в папку OneDrive.
5. Запустить discussion.py в Python 3.10+. Внешние библиотеки не требуются. На сервере нужны connection.json, team.txt и каталог data.
6. Проверить /ping, обычное обсуждение, @brb_team_admin_bot подведи итог, затем запрос «зафиксируй поручение», кнопку записи и /tasks. До этих проверок считать подключение неподтверждённым.

Программа не запускается автоматически и не установлена на сервер. Для постоянной работы нужно настроить службу после уточнения ОС. Внешние рассылки, календарные изменения и напоминания пока не выполняются.

Хранилище: data/discussion.sqlite3. Тексты старше 30 дней удаляются при поступлении нового текстового сообщения; удаления пользователями в Telegram не синхронизируются. Подтверждённые карточки сохраняются отдельно. Базу SQLite не следует одновременно открывать на нескольких компьютерах через OneDrive. Для сервера нужен локальный диск и резервное копирование.

При ошибке ответ не повторяется автоматически: запрос нужно отправить снова. Статус доставки при сетевом обрыве может остаться неопределённым. Для промышленной эксплуатации нужны очередь доставки и наблюдение за службой.
